# P1 公共运行时与工程基础

前置为已签核的 GATE-P0 与 ADR-011/012。使用 game/ 作为 Godot 资源根。各模块独立测试入口放在 game/tests/p1/<模块>/，使用真实生产脚本，任一断言失败返回非零。模块之间采用显式 preload 或注入公开端口；权威运行时不引用场景节点。root 管理 project.godot 的共享装配和阶段追踪。

| 次序 | 工作与验收 |
|---|---|
| 契约 | CON 负责规范字节、类型、错误、跨域字段和兼容。CON 端口任务独立拥有 contracts/ports/。以 production codec 读取历史 P0 字节，严格拒绝不合规范的输入，检验 NFC。 |
| 核心、定义 | CORE 和 DEF 分离。验证任务域取消、相位和随机流再现，同一 registry 的 ID、引用、循环及不可变视图。 |
| 可并行基础适配 | 按 DAG 解锁 TEST、SHRULE、INV、INF-CONTENT、PERSIST、INF-ENGINE 及 TELEM，每波最多四个。真实引擎查询、文件 IO 及回退、可重现定义摘要和事务守恒独立验收。 |
| 战役与战场 | CAMP 只经已经完成的依赖编排最小世界；MIS-RT 在适配层就绪后实现句柄守卫和生命周期。两者通过 CON 向 APP 暴露公开数据。 |
| 会话与装配 | APP 串起权威写入、模式与恢复，BOOT 装配客户端/专服的相同核心。CI 验证真实构建、启动和至少一次故障门禁。 |
| 全局门禁 | 从集成提交独立复跑领域套件、真实 GUI/headless、内容编译、迁移、提交前后断点及重复回执。仅 AT-10 的基础切片适用。 |

正式 CSV 只记录满足整个 Given/When/Then 的条目。本阶段候选用例中包含后续玩法、在线发布、多年仿真或真人容量的条目，需依据实际前置标为未执行/切片。P1 的运行框架和隔离端口进入生产目录，P0 实验留作历史输入，生产构建不依赖实验代码。

## 原创内容规模

总体规格 §1.3 保留 6–8 种文化、8–10 个初始王国，50–70 座城镇、80–120 座城堡、200–350 个村庄，80–130 个家族、500–1000 位具名英雄，150–250 个兵种与成长节点，6–10 个地貌族及文化建筑族，30–50 个动态任务模板与完整主线。正式内容按 §1.3 的质量条件验收。§23.2 要求规模结合预算冻结；当前 P0 证据覆盖一套原创程序化资产的导入和重载，正式美术、动画、关卡和叙事的生产速度、返工率及人力预算尚无数据。已向负责人征询以原区间和滚动产能安排预算，或提供具体人力和周期。最终门禁记录实际决定。
