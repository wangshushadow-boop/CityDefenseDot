# P2 专项实验：真实 Godot GDExtension 位姿批处理

在冻结组合 1d0f1fb 的千人野战中读取 MOV 提供给 COM 的固定步位姿。双方沿正式侧翼路线行进，第 917 步接敌。第 1038 步开始战斗动作判定时，记录了 1197 个实体、200 名骑手和原代码实际生成的 8379 个整数。输入包括原始位置、朝向、速度、坐骑状态及实体编号。包含三轴毫米位置、三轴朝向 ppm 和每步毫米速度的输出受相同舍入约定约束。

使用本机 Godot 4.7.2 Standard 自带的 --dump-gdextension-interface 和 --dump-extension-api，配合 Visual Studio 2022、x64、/O2 及 /fp:precise 编译实验 DLL。Godot 真实注册并调用扩展静态方法。数据来自原有 GameSession、AI 和物理，测量阶段反复读取同一张已经发生的战场快照。

每个引擎进程轮换测试 8 个入口，预热 35 轮后采样 160 轮。三次独立进程均退出 0。每个进程均逐一校验 8379 个整数与原权威结果相等，同时验证负数舍入、空批次和长度不匹配。CPU 与开发任务共享，结果用于估算热点量级。

| 每个批次处理 1197 行 | 三个进程 P50 ms | 三个进程 P95 ms |
|---|---:|---:|
| 当前 GDScript，原样产生 COM 字典 | 1.786–1.850 | 2.209–2.294 |
| 仅连续数据，GDScript 算术 | 0.265–0.267 | 0.309–0.330 |
| 仅连续数据，调用 C++ 并返回连续整数 | 0.079 | 0.087–0.102 |
| 打包原始位姿与骑手状态 | 0.427–0.430 | 0.585–0.625 |
| 从连续整数还原 COM 字典 | 0.945–0.978 | 1.275–1.386 |
| 打包、GDScript 计算、还原字典 | 1.656–1.677 | 2.083–2.185 |
| 打包、C++ 计算、还原字典 | 1.463–1.492 | 1.941–1.974 |

空批次跨语言调用的 P50 是 0.26–0.28 微秒。输入转换和恢复字典花费较大。与相同布局的 GDScript 相比，原生路线每批实际减少 0.186–0.195 ms。与原始生产代码相比，整条替代路径减少 0.323–0.359 ms。这个热点的收益不足以填补完整权威步与 16.667 ms 预算间的差距。结论仅覆盖该帧和这一项数学投影；原样逐帧替换后的全场性能、全部 CPU 架构及 8 GiB 参考机为 NOT_RUN。实验未注册生产公共端口。

初次编译遗漏 initializer_list 标头，退出 1。初次三向量试调因使用错误的 ABI 符号名终止，退出 0xC0000005。按引擎导出的头文件修正后，小样本、真实快照和三轮正式进程全部成功，正式数据保留在 trial-1/2/3.json。

在本机解包 evidence.zip 后，可以在相同 Godot 版本生成两个 ABI 文件，在该目录执行 compile.cmd，再将 pose.dll 复制至 test。以 Godot --headless --path test --script res://bench.gd -- <snapshot.bin绝对路径> <输出JSON绝对路径> 重现一次实测。清单包含源码、测试、完整快照、三次原数与结果摘要。DLL 和 8 MiB 引擎生成的接口清单可以在本机重建。
