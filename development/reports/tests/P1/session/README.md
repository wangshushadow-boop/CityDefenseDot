## AT-10 存档与事务基础切片

每轮创建沙盒地图，冻结带一个预留来源的遭遇并建立战前检查点，通过真实 MIS-RT、仿真场景和固定步推进 Mission。测试注入基础阶段尚无生产实现的结果构造和奖励规则。回执、库存单写入方、战役状态、校验、文件替换和冷启动恢复均使用生产实现。

在结算写入前、临时世界文件只写一部分、替换世界文件后但提交标记前、以及标记替换后，实际终止 Godot 进程。在进程终止前记录命中的断点。Windows 在该自终止方式下可返回 0。驱动同时校验断点标记、调用没有返回，以及断点处真实磁盘状态。每个断点另开两个独立 Godot 进程，从外部保存的同一结果字节重发，随后用 Python 读盘核对 manifest 的 SHA-256、两个账户余额、账本行、Session 回执和已应用结果数。

| 结算时断点 | 第一次恢复 | 第一次看到的付款方 / 收款方 | 首次恢复时的回执数 |
|---|---|---:|---:|
| 写入前 | 主版本 | 100 / 1 | 0 |
| 临时文件部分写入 | 主版本 | 100 / 1 | 0 |
| 提交标记前 | 上一有效备份 | 100 / 1 | 0 |
| 提交标记后 | 新主版本 | 99 / 2 | 1 |

四轮重发后均为 99 / 2，各有一笔账本和一个结果回执。再发相同结果保留原提交 ID、摘要和 revision。完整遭遇结算 AT-10 留待后续阶段复测。[原始记录](recovery.txt)
