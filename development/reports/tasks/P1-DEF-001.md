## 实现及依赖

- [注册表](../../../game/shared/definitions/registry.gd) 接收编译器注入的定义行，按 v1 DefHeader 校验，通过后一次发布。会话索引按 DefId 排序，任意加载顺序给出一致的结果。类型和标签查询返回深层只读数据。
- 编译前校验真实引用、目标种类、兵种升级和天赋前置环、装备槽位、动作窗口和数值。遇环携带闭合节点路径，失败后可用同一未发布实例重试。动态物品检查部件引用、数值、快照和既有 ID 冲突，世界保存由所属域负责。
- 内置 TroopDef、ItemDef、ActionDef 按 SDD 检查必需字段。未知顶层字段返回字段路径。可选的 `metadata` 字典供来源说明等纯展示数据使用，额外的稳定定义引用放在 `references` 并由注册表校验。首轮审查复现布尔 role 和拼错的 culture_ids 可通过；加入正反夹具、收紧字段及类型后，正式入口再次退出 0。
- 成功结果及错误复用 CON。生产装配入口为 `Registry.new().build(rows)`，按 ID 读取用 `get_definition`，按会话索引查询用 `resolve_index`。抽样查询 `list_by_tag` 按稳定 ID 排序。`validate_references()` 可重新验证已发布的引用图。

& 'D:/Program/Godot/Standard/Godot_v4.7.2-stable_win64_console.exe' --headless --log-file $defLog --path game --script res://tests/p1/definitions/run.gd
