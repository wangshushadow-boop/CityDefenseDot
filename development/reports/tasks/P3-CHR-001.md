# P3-CHR-001 · 英雄创建、成长和生命

基线为 `650adc4`。CHR 负责不可变输入产生候选英雄，CAMP/APP 在既有世界事务成功后发布候选。玩家与 NPC 使用同一个创建与成长入口。

选择文化、童年、职业、身份、外观和旗帜，验证年龄和名号，组合六属性、四项性格和十八项技能。原创建年龄和建档日可推算当前年龄。真实行为由权威调用者给出稳定来源，英雄记录其摘要。同源同载荷重放不会再次升级，内容不一致返回冲突。专精与属性影响增速及软上限，无风险练习同日递减，超过四次收益为零。技能提升推动人物升级，产生可用专精和天赋点。天赋的两个分支互斥，视图按属性和作用域返回 shared/rules 实际计算的数值和来源。

伤情与囚禁分别保存。医术、休养和过去的天数决定恢复量，同日重复结算不会额外恢复。权威结果可以区分确定的负伤、死亡和一次稳定抽样的潜在致命伤。加入已有队伍使用带类型的队伍 UUID；已有队伍成员须先离队。死亡及退休终止新的活动。历史来源仍可幂等重放。

## 本任务实测

在 Windows 上从独立工作目录使用 Godot 4.7.2 Standard 执行以下命令。正常退出码 0，输出 `P3_HERO checks=116 failures=0`。

```powershell
& "D:/Program/Godot/Standard/Godot_v4.7.2-stable_win64_console.exe" --headless --path game --script res://tests/p3/hero/run.gd
```

| 判据 | 观测 |
|---|---|
| T-CHR-01 | 六组开局选项逐项创建，18 技能及双分支数据经过校验。技能跨阈值、来源重放、异载荷冲突、点数不足、天赋互斥、加成作用域和来源通过。额外测试同日练习衰减、隔日恢复、软上限后的继续成长。 |
| T-CHR-03 | 伤后被俘，在押恢复，获释回到唯一地点，合法入队与拒绝重复入队，死亡不可复活，受伤、终态和回执经规范序列化可重载。篡改点数、技能、非法地点及矛盾状态被拒绝。 |

本任务只测试 CHR 域候选及规范编解码。实际存档、库存交接、正常菜单和终局控制权由相应集成任务验证。[测试入口](../../../game/tests/p3/hero/run.gd) · [人物规则](../../../game/campaign/character/hero_rules.json)

## 独立复核后的修订

初版的自身医术天赋只体现在角色面板，自由英雄在普通过日时也拿到休养加成。修订后，`effective_skill`、人物视图与治疗采用同一次序的作用域计算。四日自然恢复中，自身医术 +2 的伤员实际多恢复 2 点，军团范围的医术天赋不改变个人恢复。逐日与批量经过四天的终态相同。只有明确休养的自由人物获得额外恢复，被俘者按普通恢复计算。同日重复请求不增加恢复。面板新增视图字段采用字符串键，有无天赋两条轨迹均通过规范编码。按上述同一引擎命令复测，`P3_HERO checks=125 failures=0`，退出码 0。
