## 调用与提交边界

`initialize(locations, initial, authorize)` 建立账户、库存、装备槽和初始数量。货物按 DefId、品质和修饰符区分，装备实例有唯一所有者。库存容量由宿主通过 location 注入，单位为持有件数。`balance`、`available`、`owner_of`、`ledger_for` 返回 Result，查询可用量会扣除预留。

`prepare_exchange(txn_id, lines, expected_revision)` 全量预检。转账行包含 src、dst、resource、amount、reason、source_ref。单向产生或回收仅在宿主授权回调确认原因、来源及资源后通过。支持同一事务先释放预留并消费，预留、释放和转移都有准备入口。宿主在权威时间相位调用 release 处理到期预留。

APP 在单写入安全点调用 `commit(plan, durable)`。作用域版本和同 ID 请求摘要在发布前检查。可选的 durable 回调收到独立的候选全量快照和回执，可与其他域一起持久化。回调返回错误时，余额、所有者、预留、流水和去重事实均保持原值。已提交请求的重试返回原回执。提交不扫描全部库存，整份快照与载入重放按历史和库存大小计。

`restore(snapshot, authorize)` 在独立候选中从初始状态重放交易，核对余额、实例归属、预留、流水、提交版本、去重摘要和回执。历史产生/回收按已提交事实重放，新创建和回收须通过当前宿主策略。APP 只应从 PERSIST 验证过的存档加载此入口。

在上述工作区使用 Windows、Godot `4.7.2.stable.official.ed1daf0bf`。外层检查引擎退出码、错误日志和四个独立 PASS 标记。可从工作树根目录执行同一命令。


## 交易历史分卷复验

对基线 `3fcf61e40ac26984c47cef07f3263553a156e035` 的复查发现，账本达到 65,536 笔时会永久拒绝新交易。修复在内存保留按 ID 检索的去重表，导出时将超过 256 笔的历史分为每页最多 256 笔，每页一起存放有序流水、摘要与原回执。目录需要时可以分组，小型快照继续使用原先的平铺 v1 形式。读取旧 v1 平铺账本时按原表示校验，下次保存时自动分卷。

| 回归 | 运行方式 | 退出码（Godot / 外层） | 结果 |
|---|---|---|---|
| P1-INV-PAGES | 同上方命令，默认执行 | 0 / 0 | PASS。第 257 笔跨页时注入保存失败，旧快照完整；成功保存所得候选等于发布后的快照。规范编码解码并恢复后，最早交易的同请求返回原回执，改款被拒。反序页、反序流水、缺失早期去重事实均原子拒绝。从含 257 笔的旧平铺布局重读并分卷，下一笔取得 revision 258。 |
| P1-INV-65537 | 在同一命令结尾追加 `-- --long-history` | 0 / 0 | PASS。真实提交 65,537 笔交替方向转账，逐次验证回执版本；核对首末流水与第 1 笔重试及冲突，导出 257 页快照。 |

分卷复验的首轮编译因局部布尔值无法推断而退出 1。补充显式类型后，两次命令均通过，原 T-INV-01 至 T-INV-04 同时回归通过。上述 257 笔用例执行了全量编码解码和冷启动恢复，65,537 笔用例执行到快照导出。
