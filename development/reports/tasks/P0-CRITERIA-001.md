# P0 可复现实验判据

由环境调查、GDD §16.2、§19.4、§22.3、§23 及 TEST/TELEM 规格确定。以下固定输入用于本次隔离实验。引擎候选为 Godot Standard 4.7.2，试验脚本可使用 GDScript。正式端口与技术栈由 ADR 和负责人审批。

| 实验 ID | 输入、观察与验收 |
|---|---|
| B500 / B1000 | 双方等额，步兵 50%、弓手 30%、骑手 20%，坐骑另计。固定种子 241124、相同镜头轨迹与输入、相同可见范围。必须实际决策、移动、方向动作、碰撞/命中、独立蒙皮及在途弹体，记录每类实际数量、骨骼/三角形和伤亡处理。1080p、关闭 VSync，记录渲染器及具体画质配置。每档预热至少 120 个模拟 tick，再测至少 360 个模拟 tick，独占图形压测时段、每档三次。逐轮展示真实墙钟帧间隔 P50/P95/P99/最差值、平均 FPS（帧数/总时间）、最慢 1% 帧平均耗时换算的 FPS、固定 tick 路径 P95 及模拟时间相对墙钟的欠账。平均 FPS ≥60/30，帧 P95 ≤20/40 ms，tick P95 < 步长，1000 人无持续积压。三轮各自达标才能通过该档；任一轮数值失守即 FAIL。首测前将固定渲染器、1080p 中画质等效设置、镜头坐标与输入轨迹固化在同一版本脚本中。缺少画质/资产代表性只作候选采样。未采到门禁必需证据记 NOT_RUN 或 BLOCKED。 |
| B-PROFILE | 同步记录 CPU/GPU、真实硬件/驱动、实际分辨率、RSS/显存、峰值有效负载、CPU/GPU 帧时、draw calls。GPU 60 fps 档目标 16.7 ms，客户端 RSS ≤10 GB，8 GB 卡显存预算 7 GB。本机显存 24 GB，基准硬件代表性须单列。采不到的指标标出，逻辑切片与桌面图形采样分开。 |
| NAV-LINK / NAV-CROWD | 固定门洞、窄桥及楼梯/斜坡过渡，带共享路径的队列和移动代理，拥堵发生与释放均要观察到。动态关门、开门、再关闭，按导航同步后的 revision 校验端点实际可达、旧路径淘汰、不可达等待/恢复。记录人数、到达/等待、耗时、队列峰值和引擎查询成本。 |
| NET-LOOP / NET-FAULT | 真实 headless 服务端与独立进程客户端，两档并发（至少 1 与 4）、固定 30 或 60 Hz tick、10–20 Hz 快照；记录实际连接数、实体数、输入、快照、吞吐、应用层/传输层字节口径、tick P95 和积压。对照正常与固定种子的 150 ms RTT、30 ms 抖动、3% 丢包及乱序输入；确认陈旧/重复不重复生效、越权拒绝与最终状态收敛。各档 P95 tick < 固定步长，无持续积压或断线尖峰；报告测试负载上限及连接/断线。 |
| CONTENT-IMPORT / CONTENT-REJECT | 原创建模小样含蒙皮、坐骑与武器挂点、动画窗口及出生/通行标记。真实编辑器导入，加载产物、校验和编译定义，检查来源许可、坏引用、坏挂点、窗口边界；验证失败须显式退出。记录构建产物可重载情况与零售导出模板可用性。 |
| CON-VECTORS | 正反向编解码/拒绝/迁移向量必须可执行，覆盖 ID、单位、版本、所有权、tick、陈旧引用、遇敌/结果与编队端口。提出 ADR-012；批准留给项目负责人。 |

## 复跑与判读

从仓库根用本机 Python 执行实际任务脚本，公共复跑入口如下，具体参数及原始文件由任务报告记录。

```powershell
& $python test_scenarios/p0/P0-BATTLE-001/run.py --godot $godot --count 500
& $python test_scenarios/p0/P0-BATTLE-001/run.py --godot $godot --count 1000
& $python test_scenarios/p0/P0-NAV-001/run.py --godot $godot
& $python test_scenarios/p0/P0-NET-001/run.py --godot $godot
& $python test_scenarios/p0/P0-CONTENT-001/run.py --godot $godot
```

`$python` 与 `$godot` 取 ENV 报告记录的完整路径。Godot 命令选用指定目录中的 console 可执行文件，通过 `--path test_scenarios/p0/P0-<任务名>-001` 指定独立项目。NET、NAV 与 CONTENT 的服务器、导入或功能脚本用 `--headless`；B500/B1000 的图形取样使用实际显示驱动。阶段报告记录每个精确入口、版本、退出码、原始数据位置和集成提交。重复测量使用相同配置，时序故障按种子重放。错误输出、超时、丢失断言、无负载或无渲染的结果都要分别说明。性能下降时先用同一场景检查热点、调整实现并复测；保留原测量与原目标。

本阶段不授予正式游戏测试或产品需求通过状态。局域网/公网、目标硬件、美术品质和玩家手感的验证范围依实际执行记录。
