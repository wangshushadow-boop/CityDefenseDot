# P3-CHR-005 · 主菜单与人物操作授权

候选基线 `650adc4`，开发者 desktop，在独立工作树 `.worktrees/p3-desktop` 执行。任务仅涉及 BOOT 两份脚本、专属桌面测试和本报告。按 ADR-016 接入现有沙盒、GameSession 和读写存档。

主菜单在活动沙盒显示“人物”。打开、创建、重新载入各自验证当前世界，BOOT 仅向匹配令牌、Session ID 与世界 ID 的玩家命令授权。持有物查询、自由发放经验或裁定死亡没有新增按钮或操作许可。正常读取其他存档会换发能力令牌。旧人物请求按画面上的 revision 由 APP 拒绝，既有存档回执负责去重。

| 检验 | 实际入口 | 实测 |
|---|---|---|
| 桌面人物流程，T-CHR-01/02/03/04 的玩家操作 | `Godot --path game --script res://tests/p3/character_desktop/run.gd` | 合成源码、Windows 11、Godot 4.7.2、RTX 3090、Forward+、960×600。88 项通过，退出 0。原生指针点入人物并确立身世。审核伪造读取能力、非法 outcome、过期 revision，保存、关闭并重新载入角色，旧令牌拒绝。 |
| 已有桌面存读和训练 | `Godot --path game --script res://tests/p1/bootstrap/desktop.gd` | 真实 Windows 窗口，BOOT_DESKTOP_BUTTONS errors=0，退出 0。初始菜单的存档输入框数量仍为 1。 |
| BOOT/APP 回归 | `Godot --headless --path game --script res://tests/p1/bootstrap/run.gd` 和 `res://tests/p1/application/run.gd` | 两组均退出 0，BOOT_CHECKS errors=0、APP_CHECKS errors=0。 |

源级合成使用 `650adc4`、CHR、INV、APP、CAMP 及 BOOT/UI 各获准的开发文件，之后由主 Agent 另外冷构建、集成及独立验收。图形测试均使用临时 APPDATA。第一次合成导入有 Windows 编辑器 Safe save 警告，进程返回 0。改用全新的临时 APPDATA 和 LOCALAPPDATA 后，显式检查引擎日志、导入退出 0。过程中实际发现建角按钮被窄标签顶出画面和主动休养接口时序差异；调整表单与同步领域实现后同场通过。
