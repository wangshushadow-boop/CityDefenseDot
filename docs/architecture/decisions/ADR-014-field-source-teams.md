# ADR-014 · 野战预留兵源与队伍归属

**PROPOSED，2026-11-24。** 负责人已授权开始 P2。本项跨域字段语义待负责人裁定。适用战役遭遇与自定义野战，涉及 CON、Mission 部署、结果和 APP 的野战入口。

## 待定问题

v1 EncounterSpec 在 reserved_sources 中以半开区间标记兵源。Side 定义有 team_key 和 roster_allocations，但已签核契约只要求后者是数组。既有 P1 存档和训练样例允许没有兵源明细的队伍。两个队伍可以使用相同兵种，一个 Party 也可贡献多个分组，无法可靠地用数组位置或兵种推断队伍。

| 选项 | 语义与影响 |
|---|---|
| A，建议 | 保留 v1 外层。P2 野战场景使用 sides[].roster_allocations 的条目 `{"source_slot_range":[start,stop]}` 显式分配。所有区间须在已预留来源内、互斥并恰好覆盖每个来源槽；一个来源可按槽拆分，英雄单槽只能在一方。野战准备在产生任何实体前以明确字段错误拒绝不完整分配。历史训练、旧档读取及无兵源的原 P1 流程沿用已签核的 v1 兼容规则。 |
| B | 设计新版 EncounterSpec，在来源中显式保存所属队伍。需另行明确一个预留分组被多队使用时的拆分、版本协商与 v1 迁移。旧数据里没有队伍信息时需由可信的创建方补足。 |

## 验证范围

两队共享兵种、稀疏/相邻区间、越界/重复/漏分、同批部署故障回滚、千人分波及未入场状态；P1 原有训练、读取与重放。公开结果沿用已签核 MissionResult 与源槽终态。固定步内的计算、队形布局、排队和资产里程碑可以独立推进。若选 A，对冻结的外部命令封套和五个 Mission 方法的签名无改动；使用现有 FormationOrder/IntentBatch 校验身份、控制修订和重放。
